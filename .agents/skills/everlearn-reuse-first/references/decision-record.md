# 复用决策记录

| 项目     | 内容                                      |
| -------- | ----------------------------------------- |
| 需求     | 当前必须解决的具体能力                    |
| 仓库搜索 | 已检查的文件、组件和相邻实现              |
| 候选     | 官方名称、版本、链接、许可证和维护状态    |
| 适配性   | 功能、可访问性、样式、SSR、类型和运行成本 |
| 决策     | adopt、compose、thin-adapt 或 custom      |
| 拒绝项   | 不采用的关键原因                          |
| 自研余量 | 仍需编写的最小代码及不可替代理由          |
| 替换成本 | 移除或迁移时影响的边界                    |
| 批准     | 新依赖或替换方案的用户批准状态            |

只有 custom 结论需要额外回答：

1. 哪个已确认需求无法由候选满足？
2. 自研代码的唯一所有者和测试边界是什么？
3. 未来出现何种成熟方案时应删除自研实现？
