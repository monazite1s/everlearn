# 发布路线

## 排序原则

先交付知识库与 AI 编辑的可用闭环，再建设共享 Agent Runtime，最后接入自动化内容生产和账号能力。每个里程碑都必须可独立演示、测试和回滚，不以未完成的下一阶段作为验收前提。

## 里程碑

| 阶段                | 可交付结果                                                                            | 不包含               |
| ------------------- | ------------------------------------------------------------------------------------- | -------------------- |
| M0 工程基线         | Monorepo、质量命令、Design Tokens、应用壳和 Docker 依赖环境。                         | 业务功能。           |
| M1 知识库核心       | 多知识库、嵌套文档、编辑器、自动保存、修订、Inbox、回收站和附件。                     | AI、分享、协作。     |
| M2 检索与 AI 编辑   | 全局搜索、内部/反向链接、混合检索、AI 差异接受和带引用问答。                          | 后台自动化。         |
| M3 Workflow Runtime | LangGraph 持久化运行、受控工具、版本发布、运行观察和每日/每周调度。                   | React Flow 画布。    |
| M4 资讯自动化       | 资讯订阅、RSS/Search 采集、去重、质量警告和自动发布简报。                             | 登录抓取、通知中心。 |
| M5 系统教程         | 两个副作用确认闸门（表单或 Agent 对话形态）、独立建库、章节生成、引用覆盖和单章重试。 | 协作审稿。           |
| M6 Workflow 画布    | 模板、步骤编辑、React Flow 画布和版本差异。                                           | 任意 HTTP/代码节点。 |
| M7 账号与分享       | 多账号、只读公开页、过期/撤销和独立克隆。                                             | 协作者编辑。         |
| M8 生产加固         | 备份恢复、安全、性能、可观测性和完整 E2E。                                            | 多区域和微服务。     |

## 首个可用版本

M0 至 M2 完成即构成首个可用版本。用户无需等待资讯、教程或画布即可稳定建立知识库、编辑内容并使用有引用的 AI 辅助。

## 阶段门禁

- M0：`pnpm check`、本地依赖启动和主题/壳视觉基线通过。
- M1：文档树、自动保存、修订恢复和回收站 E2E 通过。
- M2：AI 接受/拒绝与引用定位 E2E 通过，模型离线时核心知识库仍可用。
- M3：运行可从检查点恢复，重试不产生重复副作用。
- M4：计划任务自动触发，同一运行只对应一个简报文档。
- M5：失败章节不阻塞其他章节，重试生成新修订。
- M6：列表和画布序列化为同一版本定义，可通过键盘完成基础编辑。
- M7：私有资源无法通过共享接口探测，克隆后独立编辑。
- M8：备份恢复演练、核心 E2E、安全检查和性能预算通过。
