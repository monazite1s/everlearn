# 页面规格：工作流

## 目的与路由

- `/workflows`：系统模板、用户 Workflow 和最近运行。
- `/workflows/new`：从模板复制或从零创建。
- `/workflows/:workflowId/edit`：步骤列表与画布编辑。
- `/workflows/:workflowId/versions`：发布历史和版本差异。
- `/workflows/:workflowId/schedules`：每日、每周计划。
- `/workflows/runs/:runId`：运行时间线、输入输出和恢复操作。
- 入口：一级导航、首页运行摘要、资讯或教程的关联运行。离开：生成文档、来源、设置 Provider 或其他一级模块。

## 数据与接口

- 数据：`Workflow`、`WorkflowVersion`、`Schedule`、`WorkflowRun`、`NodeAttempt`、`Approval`。
- 使用定义/版本、发布、Schedule、Run、确认、取消、恢复和 SSE 接口；草稿保存提交版本号。
- Workflow 版本不可变且不属于文档修订；写入知识库的节点仍必须创建对应 DocumentRevision。
- 首期固定本地用户可编辑；移动端和后续公开访问只展示安全摘要。

## 定义编辑

- 新 Workflow 首先创建草稿；名称、用途、输入、节点、连接、工具权限和输出均属于版本定义。
- 默认步骤列表完整支持添加、排序、连接、分支配置、工具参数和校验错误定位。
- React Flow 画布与列表共享同一个编辑状态和序列化器，不维护第二份模型。
- 系统模板可查看和复制，不可原地编辑；模板升级不覆盖用户副本。
- 校验通过后才能发布。发布创建不可变版本；后续编辑产生新草稿。

## 节点与工具

- 首期节点：输入、提示/LLM、知识库读取、混合检索、Web 搜索、RSS 获取、结构化输出、条件分支、受限循环、子图、人工确认、创建新文档、更新草稿、质量检查和结束。
- 循环必须声明最大次数；节点必须声明超时、重试策略和输出映射。
- 工具面板只显示内置工具及已配置 Provider Adapter；不提供 HTTP、脚本或代码节点。
- 修改已有正式文档必须经过人工确认；自动化模板只可创建新文档或更新自己创建的目标文档。

## 计划与运行

- 计划支持每日、每周和手动运行，保存时区、执行时刻、输入配置和是否启用。
- 计划默认跟随最新已发布版本；历史运行始终绑定实际版本和输入快照。
- 运行详情按 LangGraph 步骤显示待运行、运行中、等待确认、完成、失败和取消。
- 可从持久化检查点恢复；恢复会创建新尝试并保留先前记录。
- 页面停留期间完成可显示一次 Toast；不存在跨产品通知收件箱。

## 状态

| 状态 | 行为 |
|---|---|
| 空列表 | 展示内置模板和“从零创建”。 |
| 草稿无效 | 列表与画布定位同一错误；禁止发布。 |
| 等待确认 | 显示请求内容、预计副作用和批准/拒绝操作。 |
| 节点失败 | 显示可重试性、错误类别和最近检查点。 |
| Provider 未配置 | 定义可编辑，运行前校验失败并链接设置。 |
| 离线 | 定义和历史可读；编辑、发布、运行与恢复禁用。 |

## 移动端、可访问性与动效

- 移动端只读显示定义摘要、版本和运行时间线，不加载画布编辑。
- React Flow 保持节点与边键盘可聚焦，中文化 ARIA 指令；列表视图可完成所有定义编辑。
- 运行路径是首期标志性动效；reduced motion 下以节点状态和时间线即时更新替代路径运动。

## E2E 验收

1. 可从系统模板复制，也可从零创建并发布有效版本。
2. 列表和画布往返切换后定义保持一致。
3. 无效草稿不能发布；运行绑定已发布版本而不是当前草稿。
4. 未授权工具无法执行，等待确认的副作用在批准前不发生。
5. 失败运行可从检查点恢复且不重复已完成副作用。
