# ADR 003：到期清理直写 InboxItems 表的跨模块豁免

- 状态：已接受（2026-08-18）
- 关联任务：KB-11（里程碑 02 回顾审计 V4）

## 背景与约束

`TrashPurgeService`（documents 模块）永久清理到期文档子树时，必须先删除引用该子树文档的 `inbox_items.converted` 行：该外键为 `NO ACTION`，不先删会导致批次永久失败。项目规则禁止领域模块直接写他域表。

## 决策

允许 `trash-purge.service.ts` 在清理事务内直接 `DELETE FROM inbox_items`（按外键引用精确删除 converted 行），作为 G3 跨模块写禁令的**显式豁免**，理由：

1. 系统级生命周期操作：清理是跨资源的全局流程（文档子树 + 空知识库 + 其转换引用一体原子），把 inbox-items 的应用服务拉进该事务编排会将「到期对象整体消失」这一不变量拆到两个模块协同，反而提高耦合。
2. 写入面极窄：仅删除已随目标文档硬删而失去意义的转换行，无任何状态改写；converted 行不出现在任何用户列表，删除不影响用户可见行为。
3. 审计留痕：被清文档与转换关系在 `idempotency_records` 中仍保留转换响应可查。

## 备选方案与拒绝原因

- 经 InboxItems 应用服务协作：把单条 DELETE 提升为跨模块事务编排，为极窄写入面引入模块间时序耦合，收益为负。
- 修改外键为 `ON DELETE CASCADE`：需要迁移改变全局删除语义，影响面远大于本场景。

## 代价与移除条件

- 代价：documents 模块持有 inbox_items 表结构的删除知识（一个外键列）。
- 移除条件：inbox_items 引用语义变化（如保留转换历史）或清理流程重构时，重新评估本豁免并改走应用服务协作。
