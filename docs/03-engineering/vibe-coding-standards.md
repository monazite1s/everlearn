# Vibe Coding 商业化差距规范

## 0. 定位与总原则

Everlearn 的最终质量目标：UI 精致度、技术架构稳定性与扩展性对标 Notion、飞书等商业产品。开发过程以 vibe coding（快速直觉式编码）为主。

本文件把 vibe coding 模式下**最容易跳过、但决定商业级质量**的要求固化为强制门禁，作为 `AGENTS.md`、`quality-gates.md`、`development.md` 与项目 Skill 的执行补充。已有规则在本文件中以引用呈现，不重复正文；本文件只新增缺口。

总原则：

- **vibe 加速，门禁兜底**：可以快速产出，不允许快速漏项。
- **先验收后编码**：任务开始前验收标准先行，编码后按验收取证。
- **AI 自审不算评审**：关键决策与交付必须有第二视角（独立上下文评审或用户抽检）。
- **证据缺失视为未完成**：测试、走查、迁移校验必须以真实命令与结果留档，不得推断或伪造。

## 1. 差距矩阵

| 可访问性   | 键盘完整流程、焦点可见、非颜色单通道、reduced motion | 无键盘走查、对比度凭感觉       | §2.2     |

| 性能       | 有预算数字、长列表不阻塞、编辑不等待网络             | 无预算、无测量、N+1            | §2.4     |

## 2. 强制门禁

### 2.1 UI 与交互（对标 Notion/飞书的精致度）

- **状态完备**：每个页面/组件必须覆盖空、加载、部分成功、失败、离线、无权限状态；交互必须覆盖取消、冲突与恢复路径。验收时逐状态取证。
- **视觉一致性**：颜色、间距、圆角、阴影、动效时长必须引用 Design Tokens（Stylelint 已强制）；组件优先 shadcn/ui 与 `packages/ui`，禁止自研重复控件（`everlearn-reuse-first` 门禁）。
- **打磨标准**：像素级一致、焦点可见、动效克制、文案可行动；对照 `design-system.md`「商业化精致度」逐项自检。
- **新增缺口：用户可见文案集中声明**。JSX 中禁止散落裸字符串文案；文案统一为命名常量（模块内 `copy.ts` 或等价位置），为后续 i18n 预留。不强制引入 i18n 框架，是否立项多语言由产品规格决定。

### 2.2 可访问性与响应式

- 键盘可完成主流程；Dialog/Popover 焦点进入与恢复正确（`quality-gates.md`「UI 与可访问性」）。
- 状态不得只依靠颜色；动态更新用适度 `aria-live`；流式 token 不逐字播报。
- 浅色、深色、reduced motion 三态覆盖关键页面；桌面与移动只读断点各走查一次。
- **新增缺口：对比度自动校验**。设计 Token 定义即校验前景/背景对比度（WCAG AA），关键页面在视觉回归中跑 axe-core 扫描，作为 E2E 的一部分；扫描结果必须零 Critical/Serious。

### 2.3 架构稳定性

- 模块化单体；领域模块只能经应用服务、只读查询或领域事件协作，禁止跨模块直接写表（`AGENTS.md` G3）。
- 数据不变量优先 PostgreSQL 约束；索引对应已知查询；迁移事务原子化且含 up/down（`everlearn-postgres-design`）。
- 异步任务按至少一次交付设计；外部写入和文档创建必须有业务幂等约束（`development.md` 编码原则）。
- **新增缺口：失败恢复设计必须在编码前声明**。每个含异步、队列、外部 Provider 或长时间操作的切片，交付时必须明确：失败点、重试语义、降级路径、人工介入点。禁止以空 catch 或吞错实现"恢复"。
- **新增缺口：错误归属三层显式化**。基础设施层映射外部错误、应用层决定业务结果、UI 层展示可行动信息（`development.md` 已有），验收时逐层取证，禁止跨层裸抛内部错误。

### 2.4 性能预算

- **新增缺口：每页性能预算**（基线值，里程碑可修订）：

| 指标                | 预算                      | 测量方式                      |
| ------------------- | ------------------------- | ----------------------------- |
| 首屏 LCP            | ≤ 2.5s（4G 中端设备）     | production build + 浏览器测量 |
| 输入响应            | ≤ 100ms                   | 交互走查                      |
| 首屏路由 JS（gzip） | ≤ 200KB                   | 构建产物检查                  |
| 知识库树/长列表     | 500+ 节点展开不阻塞主线程 | 手动走查 + 必要时虚拟化       |

- 编辑输入不等待网络；自动保存与索引异步，失败可恢复（已有，验收时取证）。
- 列表接口不得无界返回；知识库树按需展开（已有）。
- **新增缺口：性能敏感路径在任务验收时用 production build 实测并留档数字**，不得以 dev 模式运行速度代替。

### 2.5 扩展性

- 前后端以公开契约交互；共享类型由 `packages/contracts` 派生，禁止前端手写重复类型（`everlearn-api-contract`）。
- **新增缺口：破坏性契约变更必须带迁移与兼容说明**。变更先落 `packages/contracts`，同步更新两端派生类型并跑 typecheck；影响外部消费者的变更记录兼容策略或弃用路径。
- Provider（搜索、LLM、对象存储）只经服务端 Adapter 调用，浏览器不得持有密钥（已有）。
- **新增缺口：ADR 目录**。跨模块、公共契约、数据格式、安全或供应商锁定决策写入 `docs/decisions/<NNN>-<slug>.md`（`research-and-dependencies.md` 已要求写 ADR，本文件固化位置与编号规则）。
- 设计模式按 `@designPattern` 标记并记录问题、代价、移除条件（已有）；**新增缺口：技术债登记**。任务文件的「风险」栏不得为空：无风险写"无"，有风险必须列出内容、影响与移除触发条件；未偿技术债在对应任务验收时显式确认。

### 2.6 质量验证

- 聚焦测试先行；缺陷修复必须有先失败后通过的回归测试（已有）。
- 覆盖率 80%、核心 90% 在核心流程稳定后由 `pnpm check:full` 门禁（已有节奏）。
- **新增缺口：真实环境验证取代 mock 冒充**。数据库迁移与查询以真实 PostgreSQL 验证；UI 以真实浏览器走查并截图留档；CI 之外的 Provider 以契约一致伪实现，不得以"运行通过"代替业务验证。
- **新增缺口：视觉回归基线**。核心页面稳定后建立 Playwright 截图基线（浅色/深色/reduced motion 各一）；后续 UI 任务在受影响页面跑对比，diff 需人工确认或说明。工具链随 `check:full` 里程碑一起落地。
- **新增缺口：E2E 关键闭环按里程碑分批启用**。`quality-gates.md` 列出的 6 条必需 E2E 不等到生产任务一次性补，核心闭环（知识库 CRUD、AI 修改接受/拒绝、Workflow 检查点恢复）在各领域任务完成后立即启用对应场景。

### 2.7 过程纪律与评审

- 任务开始前明确范围、非目标、验收（`everlearn-requirements`）；缺失时先修正规格，不在代码中猜测（已有）。
- **新增缺口：关键任务强制第二视角评审**。涉及数据一致性、安全、跨模块契约、UI 打磨标准的任务，在交付前由独立上下文（另一 agent 会话或用户抽检）做只读评审，评审意见与处置记录写入任务文件。普通任务至少完成自审清单（见 §3）。
- **新增缺口：安全敏感任务走安全清单**。涉及认证、分享、外部写入、Provider 凭据的任务，验收必须覆盖：输入校验、ownerId 限定、密钥不进前端、错误不泄露内部细节（`AGENTS.md`「安全与变更授权」），逐项留证。

## 3. 任务完成检查单（DoD）

每个任务验收时逐项勾选，缺项视为未完成：

1. 验收标准先行：范围、非目标、验收已在任务文件明确，未在编码中创造新需求。
2. 状态完备：空/加载/部分成功/失败/离线/无权限按页面规格覆盖并取证。
3. 组件复用：无重复自研控件；复用图或引用记录已给出。
4. 契约同步：共享类型由 `packages/contracts` 派生，两端 typecheck 通过。
5. 数据安全：查询参数化、ownerId 限定、输入校验；无密钥进前端。
6. 失败恢复：异步/队列/外部依赖的失败点、重试、降级已声明。
7. 回归保护：缺陷修复有先失败后通过测试；新逻辑有聚焦测试。
8. 静态门禁：规模/格式/Lint/类型/构建通过（`pnpm check` 对应项）。
9. 真实验证：真实数据库或真实浏览器证据，非 mock 冒充。
10. 可观测性：结构化日志与错误归属符合 `development.md`。
11. 视觉与性能：UI 任务走查三态与移动断点；性能敏感路径留预算内测量数字。
12. 证据与风险：任务文件记录改动、命令与结果；风险栏为"无"或含移除条件。
13. 关键决策：跨模块/契约/安全决策写 ADR 或任务证据，设计模式已标记。
